## Failed in-game gate

The staging byte write/sync/rename/read-back and live replacement succeeded.
Both live hashes matched the prepared pair and the journal reached `INSTALLED`.
However, this checked bytes/durability, **not whether FGO could access the renamed
files**. This was an installer defect, not a successful game-compatibility result.

On starting FGO, it requested an unexpected **1.36 GB** data download. This was
**not accepted**. FGO was force-stopped immediately; no marker or API test followed.

The replacement bundle was `0600`, owned by shell UID 2000 and group 1078. FGO
runs as UID 10075, so that shell-private file is not accessible to the game.
An unmodified neighbouring asset is game-owned with `0660`. Renaming the
shell-created staging inode carried the wrong ownership/permissions into the live
directory. Byte-hash verification cannot establish game readability.

FGO regenerated its manifest as its own UID. The preserved post-failure capture is
`local-fixtures/20261016T142712116Z-a9151763`. An opt-in local decoder comparison
found **40,955 rows in both manifests**, but installed flags changed from **1,012
to zero**. This explains the large resource-download request. The replacement
bundle itself remained unchanged. The native binary writer is not established as
accepted or rejected: the access defect prevented a valid compatibility test.

A tiny transaction-named ownership probe confirmed shell cannot `chown` a new file
to UID 10075 (`Operation not permitted`). The probe was removed. Root was not
enabled, no game check was bypassed and no world-accessible permission fix applied.

## Prevention fix

Before any live rename, staging must now match the existing game's owner/group
and owner-readable/writable access. Staged mode can be aligned with the original,
but mismatched ownership aborts staging and cleans only owned temporary files.
Commit rechecks access before replacing either live file. There is no root,
chown or world-readable fallback. This backend must fail closed rather than
install another unreadable pair.

Two new fault tests cover zero live replacements/cleaned staging on access failure,
and access rechecks at commit. The Android ownership branch still needs device
validation; JVM port tests are not a physical restore or new playback result.
