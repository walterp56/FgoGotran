# Emphasis dots: implementation and evaluation (2026-10-30)

Latest revision: ruby endpoint alignment restored and real-screenshot OCR mapping repaired on 2026-10-31; see the final section. Earlier evaluation sections record their respective snapshots.

## Behavior

- Paddle OCR retains candidate dot positions from the existing annotation-cleaning pass and maps them through existing CTC character positions. There is no additional OCR model inference. Ambiguous anchors or insufficient evidence omit decoration rather than inventing it.
- Public inputs/results carry plain text and UTF-16 emphasis ranges. Only the provider transport uses `⟦emphasized wording⟧`; private internal delimiters do not enter public results, speech, or stored source text.
- General requests add one conditional instruction only when the current source contains verified emphasis:

  > ⟦…⟧ marks visual emphasis only. Translate naturally and retain it around the corresponding wording; do not change meaning to preserve the markers.

- Translated dialogue, choices, and history draw one centered dot per letter/grapheme, excluding whitespace and punctuation. English combining accents stay with their base letter. Dots use the existing 40% ruby font scale and line space, follow proportional fitting, and reveal with each character during playback. Ruby wins an overlapping base.
- Names and bilingual Japanese originals remain unchanged. Ordinary literal `⟦⟧` source text is not interpreted as decoration. Unannotated requests keep their existing prompt/cache behavior.
- Missing or malformed model markers retain the translated body without decoration; this alone does not trigger another request or Japanese fallback. Annotated cache entries use a separate versioned namespace and validated payload without a Room migration.
- Sakura's official prompt builder/templates are unchanged. Source marker transport and safe response handling support its route without adding the general-model instruction. Actual Sakura model preservation has **not** been measured.

## Ruby rollback and missing-dot report (2026-10-31, latest)

Restored the previous ruby renderer: visible reading ink ends at the base's visible right endpoint, with the previous per-base vertical placement and endpoint-based clearance. Removed the centered-ruby helpers. The new 0.20-em circle dots remain; OCR/API ruby notation is unchanged.

The supplied device log proves loss before translation: the worlds line repeatedly logged `dots=11, ranges=0`, and the memory line logged `dots=22, ranges=5`. The latter produced only scattered dots. The cause was the strict comparison between individual glyph ink and expanded detection boxes: the detected box includes padding/occasional residual upper ink, while kana such as つ have short or low strokes. Good dot evidence was discarded.

The cleaner now attaches a verified main-ink row to an already confirmed aligned dot run. This permits matching the whole ink row to a detected line instead of requiring each kana to fill its expanded box. An actual aligned upper circle over a short kana can join that run only with matching size, height, spacing phase, nearby main ink, and no surrounding readable-ruby ink. Unverified isolated candidates retain the previous detached-kanji-stroke safeguards. Existing annotation masking and recognized body text are unchanged; no model pass or API retry is added.

Regression fixtures are exact 1699×219 dialogue crops from the user's two original Japanese screenshots: worlds and memory. Offline position captures use the bundled ONNX models with a desktop CPU probe (ONNX Runtime 1.31.1, approximate horizontal DB box postprocessing); they reproduce the logged source strings. These are frozen position fixtures, not a claim that desktop runtime and Android ORT 1.27 are identical. Automated tests rerun the production pixel cleaner and range mapper against those fixtures:

- Worlds: 12 real annotation circles map to one complete source range; the existing `六う` recognition typo is preserved rather than silently rewritten by the annotation code.
- Memory: 22 circles map to the two complete non-punctuation clauses, with no decoration on the first row.
- Padding/short-kana and wrong-row tests retain isolated-stroke rejection and prevent transfer to an adjacent row.
- Native full-render tests retain all translated characters and verify a visible annotation for every marked character in both supplied scenes. These tests supply translated spans directly; they do not assume that a new live API response will always preserve markers.

Diagnostics now include verified-dot / mapped-character counts and source / translated / rendered range counts, making future OCR, model-omission, and display issues distinguishable.
