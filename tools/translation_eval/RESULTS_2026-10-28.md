# 一般 FGO prompt 實測結果：2026-10-28

結論：採用三項有針對性證據的小幅改善：繁中標示、御主名稱獨立保護欄位，以及依當前日文選擇口癖提示。不採用沒有顯示收益的敬語／ruby 改寫。Sakura prompt、版本、原有共用角色卡和詞庫未修改。

這不是「全部翻譯已正確」或跨模型品質證明。下面的數字是本輪固定案例的首次 API 回應；沒有把單元測試、字數減少或 JSON 合格當成翻譯準確率。

## 實際設定與費用

- 官方 DeepSeek `/v1/chat/completions`，沿用 App 預設請求名稱 `deepseek-v4-flash`；實際回應模型為 `deepseek-flash`。官方說明舊 Flash 名稱是目前 Flash 的相容別名，並非本輪擅自更換後端。[模型與價格](https://api-docs.deepseek.com/quick_start/pricing)
- `temperature=1.0`、`thinking.type=disabled`、`max_tokens=256`，與目前 App 的預設 DeepSeek 請求設定一致。
- A/B 使用同一案例、目標、參數及 trial；逐組交替、組內順序隨機、串行執行。App 快取繞過；另有保存供應商的 prefix-cache token 用量。沒有用降低取樣溫度來假裝 prompt 更穩定。
- 共 **465 次**翻譯請求：45 次探索性試跑、180 次首輪 A/B、72 次角色／名稱聚焦 A/B、36 次名稱欄位 A/B、132 次額外案例 A/B。沒有額外自動評分模型或每句固定第二輪請求。
- 供應商回報：輸入 176,072 tokens，含 cache hit 78,296、cache miss 97,776；輸出 4,268 tokens。
- 依當日官方 Flash 尖峰／離峰價估算約 **US$0.0175–0.0349**。這是 token 估算，未查詢帳單或餘額；實際扣款可能受時段、方案及抵扣影響。[計價依據](https://api-docs.deepseek.com/quick_start/pricing)
- 金鑰以隱藏輸入讀取，只存在測試程序記憶體，不放命令列參數、模型訊息、程式碼、JSON 或報告。測試程序已結束。

4. 說話人、詞庫及前文是明示準備好的資料；不模擬完整 OCR、實際 DB 檢索、Android ICU、App 修復、快取或畫面渲染。Roland 截圖案例沒有重建完整 Karl der Große 詞庫命中；不能用該案例的模型通用譯名判斷實際 App 的專名檢索正確與否。
5. 一般單句／批次訊息由正式組裝函式匯出。整幕只驗證 system prompt 與正式回應契約，沒有宣稱匯出完整整幕 user prompt。編譯後的 45 組最終訊息逐筆比對，與已分別測試並接受的組件完全相同。

原始匯出、回應、正式契約驗證、費用與延遲紀錄保存在忽略的 `temp/translation-eval-deepseek-20261028/`，包含 `metrics.json`。圖片沒有上傳給 API，只有必要的日文測試文字。

## 採用的改善

### 繁中：具體標示輸出字體

一般繁中核心使用 `in-game 繁體中文 (Traditional Chinese)`；純文字契約明寫 `Return only the 繁體中文 translation`。沒有更改簡中／英文的核心語意規則；裁切、戰鬥字幕及獨立對話字幕的措辭維持原狀。

首輪 A/B 的繁中字形問題由 **17/30 降到 2/30**；最終額外案例由 **12/22 降到 0/22**。首輪仍有含設定簡字姓名的回應帶出其他簡字，不能把初步的有限字表檢查說成完整的零錯誤；最終也須保留既有繁簡處理。

字形檢查使用評測環境的 OpenCC `s2t` 作診斷，再核對可接受的正體異體字與詞義。設定姓名的字面內容排除在轉換外；`才/纔`、`吃/喫`、`裏/裡`、`爲/為` 及禁令中的 `不准` 不當成簡字錯誤。OpenCC 僅用於本地評測，沒有加入 Android App 或取代其轉換器。此項是字形符合度，並非語意準確率。

### 御主名稱：和一般詞庫的參考分開

只對帶有 `player name`／`玩家名` 註記、且 source 與 target 完全相同的設定姓名，增加一個簡短的一般模型欄位：

> Protected player names (copy exactly; never translate, transliterate or romanize):

普通詞條及說話人名稱不會因此被當成禁止翻譯的字面。共用詞庫 render 不變，新增欄位只由一般請求組裝函式使用。

原設定名稱的英文聚焦測試由 **3/6 改寫名稱降到 0/6**。但額外測試的兩種不同名稱，英文仍為 **1/4 → 1/4**：一次將假名設定名稱改成 `Gudako`。因此只可說原測試有改善，不能保證所有名字必定逐字保留；沒有加入可能誤改其他人物的強制字串替換。

### 角色口癖：保留基本口吻，按當前日文選提示

原有姓名／別名解析保持不變。新增一般模型專用的 `general_character_context_rules.tsv`，重用現有紅閻魔的基本口吻及原有條件句；當前日文沒有可能的口癖形式時，不再把帶有「啾／chirp」範例的整段提示送入請求。可能有口癖時，仍用原有完整條件指引，並保留「不可自行添加」的限制。

聚焦測試中，原文沒有口癖卻新增口癖由 **5/9 降到 0/9**；額外的普通「ち」／語氣轉折案例由 **4/12 降到 0/12**。有口癖的正例在聚焦測試為雙方 **9/9** 保留，額外測試為雙方 **6/6** 保留。

這是有限的來源形式選擇，沒有宣稱涵蓋所有日文口癖。基本角色口吻仍保留；未改共享角色資料或添加新角色事實。快取身份包含實際選取的提示文字；一般 CN/EN prompt 版本分別更新為 `jp-cn-fgo-target-v98-source-voice-literals` 和 `jp-en-fgo-target-v6-source-voice-literals`。

## 沒有採用的改寫

- 單純把角色語氣限制改寫並放在角色描述後面，未消除錯加口癖，因此保留原有 guard，用來源條件選擇提示。
- 英文 ruby 改寫沒有顯示收益。補齊現有 RAG 參考後，原有表示法已能保留兩層意思，因此未更改 ruby 指令或 `base〈ruby〉` API 表示。
- 較長的「原樣保留」詞庫註記仍有羅馬化失敗；採用獨立姓名欄位，而非堆疊註記。
- 未新增角色卡、修改共用詞條、引入逐句網搜、改變輸出上限，或增加 App 的固定第二次 AI 呼叫。

## 速度與 prompt 雜訊

最終額外案例的首次 HTTP 回應時間：

| 版本 | 樣本 | p50 | p95 |
|---|---:|---:|---:|
| 原版 | 66 | 821 ms | 1180 ms |
| 最終版 | 66 | 835 ms | 1036 ms |

中位數稍慢、尾端稍短；樣本有限、供應商 prefix-cache 與服務負載可能影響數字，**不能宣稱整體變快**。這不是 OCR 到畫面顯示的 App 端到端測量，也沒有測量實際修復率。

無口癖時省去整段條件範例；有口癖時保持原文。繁中標示及姓名保護只在對應條件出現。不能用所有請求的平均字數掩蓋不同條件，也不能把字元當 token 或雜訊分數。實際 prompt 長度差異可由 `compare-prompts` 對最終匯出重現。
